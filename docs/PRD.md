## 1. 서비스 개요

사용자의 스마트밴드(Google Health Connect / Apple Health 연동)에서 건강 데이터를 주기적으로 수집하고, AI로 분석하여 사용자·의료진·상담사가 건강 상태를 추적·관리할 수 있는 웹 기반 서비스.

### 시스템 구성

| 구성요소 | 역할                                         |
| -------- | -------------------------------------------- |
| 웹서비스 | 사용자/의료진/관리자 접속 포털 (본 PRD 대상) |
| 모바일앱 | 스마트밴드 데이터 수집 > 수집서버 전송       |
| 수집서버 | REST API 제공, 건강 데이터 DB 누적           |

## 4. 수집 건강 데이터 항목

- 기본 사항

  - 스마트밴드에 따라 수집되는 데이터 종류는 다를 수 있음
  - 수집할 수 있는 데이터를 기반으로 건강정보를 제공하고자 함
  - 개인마다 / 보유 기기마다 화면 구성은 유사하나 표시 내용은 다를 수 있음

- **미수신 항목 처리 원칙**: 기기가 지원하지 않아 데이터가 없는 항목도
  타이틀을 그대로 표시하고 값 영역에 "수집되지 않음"으로 명시한다.
  항목을 숨기지 않음으로써 모니터링 범위를 사용자가 인지할 수 있게 한다.

- Google/Apple Health 공통 기준 초안.

| 항목                  | 단위    | 수집 주기  | 비고                        |
| --------------------- | ------- | ---------- | --------------------------- |
| 심박수 (Heart Rate)   | bpm     | 1시간 평균 | 최대/최소값 포함            |
| 혈중산소포화도 (SpO2) | %       | 1시간 평균 | 미지원 시 "수집되지 않음"   |
| 수면 시간             | 시간/분 | 1일        | 깊은수면/얕은수면 구분      |
| 수면 품질             | 점수    | 1일        | 기기별 스코어 기준 상이     |
| 걸음 수 (Steps)       | 보      | 1시간 누적 |                             |
| 소모 칼로리           | kcal    | 1시간 누적 |                             |
| 스트레스 지수         | 점수    | 1시간 평균 | 미지원 시 "수집되지 않음"   |
| 체온                  | °C      | 1시간 평균 | 미지원 시 "수집되지 않음"   |
| 호흡수                | 회/분   | 1시간 평균 | 미지원 시 "수집되지 않음"   |

### 권장 스마트밴드 / 기기

서비스의 모든 수집 항목을 최대한 활용하려면 아래 기기를 권장한다.

| 기기 | 플랫폼 | 주요 지원 항목 |
| ---- | ------ | -------------- |
| Apple Watch Series 6 이상 | Apple Health | 심박수, SpO2, 수면, 걸음수, 칼로리, 호흡수 |
| Samsung Galaxy Watch 4 이상 | Google Health Connect | 심박수, SpO2, 수면, 걸음수, 칼로리, 스트레스, 체온 |
| Garmin (Forerunner / Venu 시리즈) | Google Health Connect | 심박수, SpO2, 수면, 걸음수, 칼로리, 스트레스, 호흡수 |
| Fitbit Sense 2 | Google Health Connect | 심박수, SpO2, 수면, 걸음수, 칼로리, 스트레스, 체온 |

> 위 목록은 초안이며, 실제 지원 여부는 기기 펌웨어 버전 및
> Health Connect / Apple Health API 정책에 따라 달라질 수 있다.

## 5. 화면 목록 (사이트맵)

### 5.1 공통

| 화면          | 설명                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| 로그인        | ID/PW 로그인, 역할 자동 감지 후 리다이렉트                                                               |
| 회원가입      | 사용자 등록 (Demo 플랜 기본) — 필수 입력: 이름, 이메일, 비밀번호, 핸드폰번호, 출생년도, 성별, 키, 몸무게 |
| 비밀번호 찾기 | 이메일 인증으로 재설정                                                                                   |
| 프로필 설정   | 가입 시 입력한 개인정보 수정 (키·몸무게·핸드폰번호 등), 알림 수단 설정 (2차 구현)                        |

### 5.2 사용자 화면

**대시보드** — 전문 의료 서비스 비주얼 중심 설계
- ① 건강 점수 원형 게이지 (0~100) + AI 판정 등급 뱃지
- ② 헬스 링 (걸음수·칼로리·활동시간)
- ③ 핵심 지표 카드 4종 (심박수·SpO2·수면·스트레스)
  - 측정치 vs 표준치(연령·성별 기준) 나란히 표시 + 7일 스파크라인
- ④ 24시간 히트맵 (시간대별 심박수/활동량 색상 표현)
- ⑤ AI 종합의견 패널
- ⑥ 수면 단계 바 (깊은수면·얕은수면·REM)
- ⑦ 위험/이상 판정 시 상단 강조 배너 자동 표시

**QR 코드 발급** — 앱 연동용 QR 생성 및 표시

**일간 리포트**
- 날짜 선택기
- 24시간 다중 라인 차트 (항목별 오버레이, 이상 구간 하이라이트)
- 시간대별 측정치 테이블 (측정값·표준범위·상태 아이콘 포함)
- AI 분석 결과
- PDF 다운로드 (A4 인쇄용 HTML→PDF)

**주간 리포트**
- 7일 트렌드 바+라인 복합 차트
- 항목별 일평균 vs 표준치 비교 테이블
- 전주 대비 변화율 표시
- 주간 종합의견
- PDF 다운로드

**월간 리포트**
- 월별 캘린더 히트맵 (판정 등급 색상)
- 30일 추세 라인 차트
- 항목별 월평균·최대·최소 통계 테이블
- 전월 대비 비교 / 장기 추세 코멘트
- PDF 다운로드

**알림 이력** — 수신된 알림 이력 조회 (2차 구현)

**상담 이력** — 상담사와의 통화 상담 이력 조회
- 표시 항목: 상담 일시, 내용 요약, 후속 조치

**분석 구간 설정** — 나만의 24시간 분석 시작 시각 설정

**AI 건강 조언** — 현재 사용자 상태에 맞는 건강 조언 및 생활 개선 제안
- 건강 데이터 기반 현재 상태 요약
- 아래 주제별 맞춤 개선 제안 (해당 항목만 표시)

| 주제      | 제안 예시                                      |
| --------- | ---------------------------------------------- |
| 운동      | 권장 걸음수 달성 여부, 유산소·근력 운동 제안   |
| 식단      | 칼로리 소모 대비 활동량 피드백, 수분 섭취 권고 |
| 수면      | 수면 시간·질 개선 팁, 취침 시각 조정 제안      |
| 스트레스  | 스트레스 지수 추이 기반 이완 활동 제안         |
| 생활 패턴 | 활동 집중 시간대 분석, 장시간 비활동 경고      |
| 심혈관    | 심박수·SpO2 이상 시 주의사항 안내              |

| 화면             | 주요 내용                                                                                       |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| 상담 대기 목록   | 의사 인계 또는 위험 알림 대기 목록                                                              |
| 고객 뷰어        | 고객 선택 시 사용자 화면과 동일한 구성 표시 (아래 별도 정의)                                    |

| 사용자 대리 등록 | 내방 사용자의 계정 생성 및 기본정보 입력 대행, QR 발급 후 모바일 앱 설치·연동 현장 지원         |
| 이용기간 관리    | 사용자별 서비스 이용 기간 조회·지정·연장                                                        |
| 상담 이력        | 완료된 상담 목록 조회                                                                           |

#### 고객 뷰어 상세

상담사가 고객을 선택하면 해당 고객의 사용자 화면과 **동일한 구성**을 조회할 수 있다.
원활한 전화 상담을 위해 고객이 보는 화면 그대로를 상담사도 볼 수 있어야 한다.

**표시 범위**: 사용자 화면 전체 (대시보드·일간·주간·월간 리포트·AI 건강 조언 등)

**개인정보 마스킹 규칙**

| 항목        | 표시 방식                                   |
| ----------- | ------------------------------------------- |
| 이름        | 전체 표시 (마스킹 없음)                     |
| 이메일      | 앞 3자리만 표시 (예: `hea****@example.com`) |
| 핸드폰번호  | 가운데 4자리 마스킹 (예: `010-****-5678`)   |
| 출생년도    | 전체 표시 (연령 참고용)                     |
| 성별        | 전체 표시 (분석 기준값)                     |
| 키 / 몸무게 | 전체 표시 (건강 분석 기준값)                |

- 마스킹은 서버 응답 시점에 적용하며, 프론트엔드 단에서 해제 불가
- 건강 데이터(측정값·AI 분석 결과 등)는 마스킹 없이 전체 표시

## 6. 주요 기능 명세

### 6.1 회원가입 & QR 연동 흐름

**[경로 A] 사용자 직접 가입**
```
[웹] 회원가입 → 플랜 선택 → 가입 완료
       ↓
[웹] QR 코드 발급 화면 진입 → Unique Key 기반 QR 생성
       ↓
[앱] QR 카메라 스캔 → Unique Key 등록 → 수집서버 연결
       ↓
[앱] 이후 1시간 단위로 건강 데이터 자동 전송
```

**[경로 B] 상담사 대리 등록 (내방 사용자)**
```
[상담사 웹] 사용자 대리 등록 → 계정 생성 + 필수정보 입력(이름·이메일·핸드폰번호·출생년도·성별·키·몸무게) → 이용기간 설정
       ↓
[상담사 웹] QR 코드 발급 → 사용자 스마트폰에 QR 표시
       ↓
[현장] 사용자 스마트폰에 모바일 앱 설치 안내 → 앱 실행 후 QR 스캔
       ↓
[앱] Unique Key 등록 → 수집서버 연결 → 데이터 수집 시작
```

### 6.2 AI 분석 파이프라인

```
[수집서버] 1시간마다 데이터 누적
       ↓
[웹서버] 사용자별 분석 구간(24시간) 종료 시 데이터 수집
       ↓
[AI] 1차 분석 → 항목별 이상 감지
       ↓
[AI] 매일 밤 일간 종합의견 생성 → DB 저장
       ↓
[알림] 위험/이상 판정 시 알림 발송 (2차 구현)
```

### 6.3 위험 케이스 처리 흐름

```
AI 위험 판정
       ↓
의사 → 위험환자 목록에서 확인 → 의견 작성 → 상담사 인계 여부 결정
       ↓ (인계 시)
상담사 → 상담 대기 목록 수신 → 사용자 통화 → 통화 기록 저장
       ↓ (필요 시)
상담사 → 병원 예약 대행
```

| 주의 | 노란색 | 1개 이상 항목 경계값 초과          |
| 이상 | 주황색 | 복수 항목 이상 또는 지속 악화 추세 |
| 위험 | 빨간색 | 즉각 조치 필요 수준                |

### 판정 방법 및 조치

- LLM AI를 이용하여 등급을 정의하고 분류토록 한다.
- AI가 제공하는 정보는 보조 수단으로 1차 정보 제공에 의미가 있다.
- AI가 이상/위험 분류 사용자에 대해서는 의사가 최종 검토한다.
- 이후 진행은 의사의 판단에 따라 진행된다. (오프라인으로 연결)

### 화면 표현 방식

> **사용자 화면 디자인 원칙**: 전문 의료기관이 제공하는 서비스라는 신뢰감과 첨단 헬스케어 플랫폼의 인상을 줄 수 있도록 설계한다. 단순 데이터 나열이 아닌, 임상적 맥락이 느껴지는 시각화를 목표로 한다.

#### 공통 UI 원칙

- **측정치 vs 표준치 병렬 표시**: 모든 수치 지표에 사용자의 측정값과
  연령·성별 기준 표준 범위를 함께 표시하여 맥락을 제공
- **시간순 비교**: 이전 기간(전일/전주/전월) 대비 변화를
  수치와 방향 아이콘(↑↓)으로 명시
- **상태 시각화**: 정상/주의/이상/위험 구간을 색상 밴드로 차트에 오버레이
- **의료 신뢰감 톤**: 라이트 모드 기본, 차분한 딥 블루/네이비 계열 베이스
  + 포인트 컬러, 클린한 타이포그래피, 불필요한 장식 배제
  (다크 모드는 2차 구현 시 선택 옵션으로 고려)
- **수집 데이터 최대 노출**: 수집된 모든 건강 데이터를 빠짐없이 화면에
  표시하여 사용자가 자신의 건강 상태가 촘촘하게 모니터링되고 있음을
  직관적으로 느낄 수 있도록 한다. 데이터가 없는 항목은 숨기지 않고
  "미수신" 또는 "측정 안됨" 상태로 명시하여 모니터링 범위를 인지시킨다.

#### 화면별 시각화 상세

| 화면         | 주요 차트/표                                                                        | 비교 축                        |
| ------------ | ----------------------------------------------------------------------------------- | ------------------------------ |
| 대시보드     | 원형 게이지, 헬스 링, 지표 카드(스파크라인), 24시간 히트맵, 수면 단계 바            | 측정치 vs 표준치(연령·성별)    |

| 주간 리포트  | 7일 바+라인 복합 차트, 항목별 일평균 비교 테이블, 변화율 표시                       | 표준치 기준선, 전주 대비       |

| AI 건강 조언 | 상태 요약 카드, 주제별 개선 제안 카드 (운동·식단·수면·스트레스·생활패턴·심혈관)     | 사용자 추세 기반               |

모든 수치 테이블은 아래 컬럼 구조를 기본으로 한다:

| 항목   | 측정값 | 표준 범위  | 상태   | 전기간 대비 |
| ------ | ------ | ---------- | ------ | ----------- |
| 심박수 | 72 bpm | 60–100 bpm | 🟢 정상 | ↓ 3 bpm     |

| …      | …      | …          | …      | …           |

- **종합의견**: AI 생성 텍스트 요약 (3~5문장) + 판정 등급 색상 배경 강조

### AI 분석 리포트 출력 형식

LLM AI가 생성하는 분석 결과는 **인쇄용 HTML 문서**로 제작하며, 오프라인 건강정보 차트(의료기관 발급 서류) 스타일로 디자인한다.

#### 출력 규격

| 항목          | 내용                               |
| ------------- | ---------------------------------- |
| 기본 포맷     | HTML (웹 렌더링 + 인쇄 최적화)     |
| 다운로드 형식 | PDF (HTML → PDF 변환 제공)         |
| 용지 크기     | A4 (210 × 297 mm)                  |
| 여백          | 상·하·좌·우 15mm (인쇄 여백 기준)  |
| 폰트          | 인쇄 가독성 우선, 한글 지원 웹폰트 |

#### 리포트 구성 (A4 기준)

- **1페이지**: 사용자 정보(이름·출생년도·성별) + 분석 기간 + AI 판정 등급 + 종합 의견 요약
- **2페이지~**: 항목별 측정값·표준치·상태 테이블 + 시각화 차트 (페이지 자동 분할)
- **마지막 페이지**: 면책 고지 (AI 분석은 보조 수단이며 의료 진단을 대체하지 않음)

#### 디자인 원칙

- 배경 흰색, 텍스트 검정 계열 — 인쇄 시 잉크 절약 및 가독성 확보
- 차트는 SVG 또는 Canvas → 이미지 변환 방식으로 PDF에 포함
- 웹 화면 UI(다크 테마, 애니메이션 등)와 별도로 `@media print` CSS 분리 적용
- 헤더(로고·서비스명)·푸터(페이지 번호·생성일시) 각 페이지에 고정 출력

## 8. 알림 정책 (2차 구현)

> **알림 기능 전체(Push·SMS·Email)는 2차 구현 범위로 이관한다.** 아래 정책은 구현 시 기준 문서로 활용한다.

| 트리거                  | 수단             | 수신자 | 시점              |
| ----------------------- | ---------------- | ------ | ----------------- |
| AI 위험 판정            | Push(FCM)        | 사용자 | 즉시              |
| AI 이상 판정            | Push(FCM)        | 사용자 | 즉시              |
| 일간 리포트 생성 완료   | Push(FCM) (선택) | 사용자 | 매일 분석 완료 후 |
| 위험환자 신규 발생      | Push(FCM)        | 의사   | 즉시              |
| 상담 인계               | Push(FCM)        | 상담사 | 즉시              |
| Demo 기간 만료 D-7, D-1 | Email            | 사용자 | 자동 발송         |

> Push 알림 구현 방식: **FCM(Firebase Cloud Messaging)** 으로 확정 (2차 구현 시 적용)

### 8.1 알림 내용 정책 (2차 구현)

알림은 **상세 조회 페이지 링크/딥링크만 포함**하며, 실제 건강 데이터 및 분석 내용은 웹서비스 로그인 후에만 확인 가능한 구조로 설계한다.

| 알림 수단 | 발송 내용                      | 상세 내용 확인 방법                 |
| --------- | ------------------------------ | ----------------------------------- |
| Push(FCM) | 알림 유형 + 상세 페이지 딥링크 | 딥링크 탭 → 웹서비스 로그인 후 조회 |
| SMS       | 알림 유형 + 상세 페이지 링크   | 링크 클릭 → 웹서비스 로그인 후 조회 |
| Email     | 알림 유형 + 요약 + 상세 링크   | 웹서비스 로그인 후 전체 조회 가능   |

- 알림 본문에 건강 수치·AI 판정 결과 등 민감 데이터를 포함하지 않는다.
- 로그인 없이 접근 가능한 링크는 허용하지 않으며, 링크 접속 시 로그인 페이지로 리다이렉트된다.
