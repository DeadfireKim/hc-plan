## 1. 사용자 역할

### 1.1 역할 정의 (5종)
영문 식별자는 glossary와 호환 유지 (DB·API·코드 변경 금지).

| 역할 | 영문키 | 누구 | 핵심 역할 |
|---|---|---|---|
| **관리자** | `operator` | **서비스 운영사(우리)** 측 슈퍼어드민 | 병원 생성, 와치관리자 배정, 전체 관리, 전 권한 |
| **와치관리자** | `watch` | 병원 운영 인력 (**일반인 가능**, 비의료인) | 의료진·시니어 등록, **의료진↔시니어 매핑**, 기기 관리 |
| **의료진** | `medical` | 의사·간호사 | 담당 시니어 모니터링, **상담(의료인만)**, 소견 / `[Max]` 콜센터 상담 간호사 포함 |
| **시니어** | `senior` | 프리미엄 시니어 | 데이터 소유자(Owner), 앱 사용, 와치 착용 본인 |
| **보호자** | `child` | 자녀 | 이상상황·월간레포트 수신, 대리 온보딩·결제 |

### 1.2 역할 운영 원칙
- 관리자(`operator`)는 **서비스 운영사 측**(병원 소속 아님). 병원을 생성하고 와치관리자를 병원에 배정한다.
- **병원 내 최고 권한 = 와치관리자.** 일반인(비의료인)도 담당 가능.
- **상담·소견·콜센터 응대는 의료인(의사/간호사)만.** 와치관리자는 운영 업무만, 의료 행위 불가.
- `[Max]` 콜센터 상담 간호사는 별도 역할을 만들지 않고 **`의료진` 역할로 편입**한다.

### 1.3 역할 간 관계·제약
| 관계 | 카디널리티 | 비고 |
|---|---|---|
| 시니어 ↔ 의료진 | **N:N (제한 없음)** | 시니어 1명에 복수 의료진(의사·간호사) 매핑 가능 / 의료진 1명당 담당 시니어 무제한 |
| 시니어 ↔ 보호자 | **1:N (최대 3명)** | 시니어 본인 승인 전제 |
| 시니어 ↔ 와치 | **1:1** | 한 시니어가 와치 하나 |
| 병원 ↔ 와치관리자 | 1:N | 병원당 와치관리자 복수 가능 (음성: 병원 등록 시 옵션 추가) |

### 1.4 역할 겸직 (멀티롤)
- **한 계정이 복수 역할을 보유할 수 있다.** 권한은 **보유 역할들의 합집합(union)**으로 계산.
- 대표 사례: 간호사가 운영도 하는 경우 → `watch` + `medical` 동시 보유 → 운영 기능 + 건강데이터 열람.
- 덕분에 일반인 와치관리자(`watch`만)는 건강데이터를 못 보고, 열람이 필요한 직원은 `medical`을 추가 부여하면 된다. (§2.1 참조)

## 2. 권한 매트릭스

> 권한은 **역할별 권한의 합집합**으로 계산(§1.4 멀티롤). 겸직 시 더 넓은 권한 적용.

### 2.1 건강 데이터 열람 권한
| 데이터 | 관리자 | 와치관리자 | 의료진 | 시니어(본인) | 보호자 |
|---|:-:|:-:|:-:|:-:|:-:|
| 자동수집(심박·걸음·SpO₂·체온·혈압·체성분·수면) | 전체 | ✘ | 전체 | 전체 | 이상시+월레포트 |
| 수동입력(혈당·체중) | 전체 | ✘ | 전체 | 전체 | 이상시+월레포트 |
| 위치정보 | 전체 | ✘ | ✘ | 전체 | 이상시 |
| `[Max]` 사용패턴·사회적고립 | 전체 | ✘ | 요약 | 전체 | 이상시 |

- **와치관리자는 건강 데이터 열람 불가**(기기 연결상태·수집 현황 등 운영 정보만). `medical` 겸직 시 의료진 권한으로 열람.
- 보호자는 D-09대로 **이상상황 + 월간레포트만** (상세 수치 비표시).
- 위치정보는 의료진도 차단(진료목적 외 사생활 보호 — glossary §7).

### 2.2 운영·관리 기능 권한
| 기능 | 관리자 | 와치관리자 | 의료진 | 시니어 | 보호자 |
|---|:-:|:-:|:-:|:-:|:-:|
| 병원 생성·관리 | ✔ | ✘ | ✘ | ✘ | ✘ |
| 계정 생성·관리 | ✔ 전체 | ✔ (관리자 제외) | ✘ | ✘ | ✘ |
| 의료진↔시니어 매핑 | ✔ | ✔ | ✘ | ✘ | ✘ |
| 보호자 매핑 | ✔ | ✔ | ✘ | ✔ 승인 | ✘ |
| 와치 연동·대여 | ✔ | ✔ | ✘ | 셀프 | 대리 |
| 신체정보 입력 | ✔ | ✔ | ✘ | ✔ 본인 | ✘ |
| 건강데이터 수동입력(혈당·체중) | ✔ | ✘ | ✔ | ✔ 본인 | ✘ |
| 복약 등록·관리 | ✔ | ✘ | ✔ 처방 | ✔ | ✔ 대리 |
| 일정 등록·관리 | ✔ | ✘ | ✔ | ✔ | ✔ 대리 |
| 상담·소견 작성 | ✔ | ✘ | ✔ | ✘ | ✘ |
| 공지 등록 | 전체 | 병원범위 | 매핑시니어 | 조회 | 조회 |
| 대시보드 | 전체범위 | 병원범위 | 매핑시니어 | 앱홈 | 앱 |
| `[Max]` 구독·결제 | ✔ | ✘ | ✘ | 본인 | ✔ 대리결제 |
| `[Max]` 컨시어지 예약 | ✔ | ✘ | ✔ 상담 | 요청 | 대리요청 |

- 계정 생성은 **PC에서만**. 와치관리자는 관리자(operator) 제외 전 역할 생성 가능. 의료진은 계정 생성 불가. 시니어는 PC 로그인 불가(앱 전용).
- **보호자 대리 케어**: 복약·일정·`[Max]`대리결제 허용. **신체정보·수동 건강데이터 입력은 시니어 본인만.**
- **공통 원칙**: 건강데이터 **삭제 불가**(전 역할). 보호자가 변경 시 **시니어에게 통보**. 시니어 본인 결정이 관리자 설정보다 우선(glossary).

### 2.3 공개 범위(2차 범위) 정의
| 레벨 | 의미 |
|---|---|
| 전체 | 원본 측정값까지 조회 |
| 요약 | 일평균·범위·이상여부 등 가공 요약만 |
| 이상시 | 이상징후 발생 시에만 노출 (보호자 기본값) |
| 비공개 | 항목 자체 비표시 |

- **"2차 범위"** = 시니어 **동의로 부여되는 조건부 공개**. 시트의 "2차 범위" 표기는 보호자에게 시니어가 허용한 범위를 뜻함.
- **우선순위**: 시니어 본인 설정 > 관리자 설정 (시니어 결정 최우선, glossary §5).
- 관리자(`operator`)는 시스템상 전체 접근(감사 로그 대상 — §11).

## 3. 인증·계정

### 3.1 로그인 정책
- `[Min]` **구글 계정 전용** 로그인. 계정 없으면 구글 가입 필요.
- 고령 시니어 진입장벽은 **대리 온보딩**(§3.2)으로 해소 — 시니어 본인은 직접 가입 절차 없음.
- `[Max]` 카카오 등 소셜 로그인 추가.
- 플랫폼: 시니어·보호자 = **앱**, 관리자·와치관리자·의료진 = **PC**. (시니어는 PC 로그인 불가)

### 3.2 계정 생성·온보딩
- 계정 생성은 **PC에서만** (관리자 / 와치관리자). 와치관리자는 관리자 제외 전 역할 생성. 의료진은 생성 불가.
- **시니어 온보딩 흐름**:
  1. 와치관리자(또는 자녀)가 시니어 계정 생성
  2. 시니어별 **QR 자동 생성**
  3. 시니어 폰에 앱 설치 + QR 스캔 → 구글 연동 + 와치 페어링
  4. 완료 — 시니어는 복잡한 가입 절차 없이 시작
- **자녀 대리 온보딩**(D-10): 자녀가 부모 가입·연동·결제 대신. "모시고 오거나 / 폰만 갖고 오거나 / 온라인 셀프"

### 3.3 계정 탈퇴
- **소프트 삭제** (물리 삭제 아님 — 복구·감사 가능).
- 탈퇴 시 **"그동안 수집된 모든 데이터가 삭제됩니다"** 문구 필수 고지.

## 4. 와치·기기

> **glossary §4 정책 전체 승계** — 소유유형(rental/personal), Tier1~3+unsupported, 기기 상태머신 9단계, 페어링 진입점, 회수정책, 하이브리드 케이스. 상세는 glossary 참조, 본 절은 v3 적용 범위만 명시.

### 4.1 소유 유형
- **대여형(`rental`)**: 병원 자체 와치 대여. 와치관리자가 페어링. (병원 자산, 자체 와치만 허용)
- **본인형(`personal`)**: 시니어·자녀가 구매(선물 포함). 셀프/대리 페어링. (Tier 화이트리스트)
- 시니어 ↔ 와치 = **1:1**(§1.3). **건강데이터는 기기가 아닌 시니어 계정에 귀속**(회수해도 데이터 유지).

### 4.2 지원 기기 / Tier
| 항목 | 🟢 Min | 🔵 Max |
|---|---|---|
| 지원 Tier | Tier1(자체·애플·갤럭시) | + Tier2(Fitbit·Garmin)·Tier3(샤오미) |
| 정확도 표시 | 지원/미지원 단순 | 기기별 정확도 배지 고도화 |
| 신규기기 | — | 스마트링·칩 등 수용 |
| 혈당 | 미지원 → 수동입력 보완(D-03) | 기기 지원 시 자동수집 전환 |
- 화이트리스트 기반 — `unsupported` 기기는 페어링 차단(active 저장 불가).

### 4.3 페어링
- 진입점: 와치관리자 콘솔(대여형) / 모바일 셀프(본인형) — glossary §4.5
- QR 스캔 + BLE 우선, 시리얼 수기는 폴백(고급 토글). 본인형은 본인인증 1회.
- `[Max]` Tier 강등 시 90일 사전 고지.

### 4.4 회수 (대여형)
- glossary §4.7 따름: 회수 사유 5종(`expired/lost/deceased/replaced/user_request`), 회수 후 24시간 누락 데이터만 허용, 점검 후 재고복귀/폐기.

## 5. 건강 데이터

### 5.1 수집 항목·주기
| 항목 | 주기 | 수집 방식 |
|---|---|---|
| 심박수 · 걸음수 | 실시간 | 와치 자동 |
| SpO₂ · 체온 | 10분 | 와치 자동 |
| 혈압 · 체성분 · 수면 | 1일 | 와치 자동(기기 지원 시) |
| 혈당 · 체중 | 수시 | **앱 수동입력**(D-03) |

### 5.2 비교 기준
| 기준 | 🟢 Min | 🔵 Max |
|---|:-:|:-:|
| 본인 기저선(평상시) 대비 % | ✔ | ✔ |
| 어제 대비 | ✔ | ✔ |
| 또래평균(코호트 동적 정상범위) | — | ✔ |
| 목표 대비 | — | ✔ |
- **또래평균은 절대치가 아님** = 자사 고객군 평균 기반 **동적 산정**(정기 갱신, D-06). 데이터 축적이 필요해 **Max**에 배치.

### 5.3 이상징후 판정·알림
- **본인 평상시 대비 % 변화**가 판정 핵심(Min). AI **민감도 우선**(놓치지 않기) → "병원 가보세요" 가이드, 최종판단은 의사(D-07).
- **임계치 = 시스템 기본값 + 의료진/관리자 항목별 조정.**
- 알림 대상: 본인+자녀(기본) / `[Max]` +의사·간호사(고급 등급). → §8 알림 연계.

## 6. 복약 관리
- 복약 일정 등록·수정: 의료진(처방) · 시니어 본인 · 보호자(대리, D-20) · 관리자/와치관리자(PC).
- **복약 알람**: 앱에서만 동작. **복약 완료 버튼을 눌러야 알람 정지**, 안 누르면 **30분 단위 재알림**(시트 명시).
- 미복약 시 자녀에게 2차 알림.
- `[Max]` 의료진 처방 변경 → 앱 자동 반영·알림.

## 7. 일정 관리
- 일정 유형: 병원 예약 · 검진 · 운동 · 기타.
- 등록·수정: 시니어 본인 · 보호자(대리, D-20) · 의료진 · 관리자/와치관리자.
- **해당 일정 시각에 앱 알람.** 병원 예약은 D-3 / D-1 / 당일 알림.
- `[Max]` 컨시어지 예약(전국 병원)과 연계.

## 8. 알림·공지

### 8.1 알림 유형
| 유형 | 대상 | 비고 |
|---|---|---|
| 이상징후 | 본인+자녀 / `[Max]` +의사·간호사 | 평상시 대비 %, "병원 가보세요" 가이드(D-06·07) |

| `[Max]` 사회적 고립 안부 | 본인 | 사용패턴 기반, **수집 방법 미정**(D-11) |

### 8.2 발송 채널
- **앱 푸시 기본 + 카톡/메일**(D-19). 앱 미설치 보호자도 핵심 알림 수신.

### 8.3 공지사항
- 앱은 **조회 전용**(등록 기능 없음). **종 아이콘 빨간점**으로 신규 공지 표시(시트).
- 등록 권한: 관리자(전체) / 와치관리자(병원범위) / 의료진(매핑 시니어) — §2.2.

### 8.4 응급·안전 (SOS) `[Min]`
- **낙상 감지 → 자동 SOS**: 와치 가속도 센서 감지, **30초 무반응 시 자동 발신**.
- **SOS 버튼**: 앱 홈 화면 고정. 자녀·119·주치의 **원터치 호출**.
- **응급 시 위치 자동 공유**: SOS/낙상 발생 시에만 보호자에게 위치 전송(평소엔 차단 — §2.1 위치정보 "이상시").
- 발신 대상: 자녀 전원 기본 + 등급별 의료진/콜센터(`[Max]`).
